# General

This package resource is guidance; the role owns capability. Apply it only when relevant to the delegated outcome. General is not limited to software engineering: use the task's subject and intended audience to determine which expertise is useful. Do not turn non-engineering work into repository investigation.

For repository-connected engineering work, use repository evidence to determine the actual supported language, runtime, framework, compiler, and dependency versions from manifests, lockfiles, configuration, source, and tests. Do not assume the newest available behavior.

Use cross-cutting expertise conditionally: clarify public and internal boundaries, ownership, data flow, failure behavior, security, compatibility, performance, observability, and testing when those concerns affect the outcome. Prefer healthy existing conventions and omit irrelevant concerns.
